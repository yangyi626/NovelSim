# 长期记忆检索评测

> 基准版本：中文剧情长期记忆基准 v1
> 实测日期：2026-07-26
> 模型：`text-embedding-3-small`（1536 维）
> 检索范围：按 `session_id + character_id` 严格隔离，Top-K = 4

## 基准组成

- 25 条容易相互干扰的剧情记忆：阴谋、物品藏匿、人物承诺、地点、债务、道路、身份线索等。
- 50 个中文查询，每条记忆包含一个同义改写查询和一个关键词查询。
- 角色分为夜清清与林管家；正确答案不允许跨角色记忆作用域。
- 正确答案使用稳定的 `source_event_id`，不依赖运行时随机生成的 `memory_id`。

基准文件：[`benchmarks/memory_retrieval_zh.json`](../benchmarks/memory_retrieval_zh.json)

## 指标

- `Hit@4`：Top-4 中是否至少出现一个正确答案。
- `Recall@4`：正确答案被召回的比例。
- `MRR`：第一个正确答案排名的倒数均值，越接近 1 越好。
- `nDCG@4`：兼顾是否命中与命中位置的排序质量。
- `irrelevant`：返回候选中非标注答案的比例。当前多数查询只有一个标注答案，因此返回满 4 条时理论下限就是 75%，该指标主要用于跨版本异常监控。
- `P95`：本机单次召回的 95 分位延迟，不包含首次批量生成 benchmark embedding 的时间。

## 真实评测结果

| 方案 | Hit@4 | MRR | nDCG@4 | P95 |
|---|---:|---:|---:|---:|
| SQLite FTS5 | 0.840 | 0.805 | 0.814 | 5.7 ms |
| 旧混合权重（语义 45 / 词法 35） | 1.000 | 0.907 | 0.930 | 18.7 ms |
| 语义 60 / 词法 20 / 重要度 15 / 新近性 5 | 1.000 | 0.927 | 0.945 | 10.1 ms |
| 语义 70 / 词法 15 / 重要度 10 / 新近性 5 | 1.000 | 0.947 | 0.960 | 11.4 ms |
| **语义 80 / 词法 10 / 重要度 5 / 新近性 5** | **1.000** | **0.957** | **0.967** | **15.7 ms** |
| 纯语义 | 0.980 | 0.953 | 0.960 | 25.5 ms |

最终采用 80/10/5/5。相比 FTS5：

- Hit@4：84% → 100%。
- MRR：0.805 → 0.957。
- nDCG@4：0.814 → 0.967。
- P95 仍在本机毫秒级。

纯语义会漏掉一条“从展示力量推断并非弱者”的间接表达，证明保留少量词法、重要度和新近性信号有价值。

## 本轮修正

1. 余弦相似度从“线性压缩 `[-1, 1]` 到 `[0, 1]`”改为“负数截断为 0、正数保留原值”。这能保留高相关候选之间的区分度，避免词法首位被过度放大。
2. `OpenAICompatibleEmbedder` 增加批量 embedding。
3. 评测前一次性预热并缓存 75 段文档与查询向量，真实网关只请求 1 次。
4. 权重成为显式 `HybridRetrievalWeights`，后续可以继续对比而无需改动检索流程。

## 运行

```powershell
.venv\Scripts\python.exe -m engine.evaluate_memory_retrieval
```

默认发布门槛：

- Hit@4 ≥ 0.85
- MRR ≥ 0.65
- nDCG@4 ≥ 0.70
- 最佳混合召回的 Hit@4 不得低于 FTS5 基线

保存逐查询 JSON：

```powershell
.venv\Scripts\python.exe -m engine.evaluate_memory_retrieval `
  --output data/memory-retrieval-report.json
```
