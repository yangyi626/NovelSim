# 结构化场景评测与消融

## 1. 目的

这套评测回答的不是“文字看起来是否精彩”，而是以下可从权威证据计算的问题：

- 场景是否到达预期结局，核心目标是否完成；
- ToolCall 是否成功，非法调用是否以预期结构化原因被拒绝；
- 是否提交非法 Patch、未知实体、因果越权或认知泄漏；
- 信息传播、证据链、联盟和事件回放是否一致；
- Free/Script 在固定种子下是否得到相同权威终态与工具链；
- 各阶段延迟、模型调用、输入/输出 Token 和成本是多少。

主观写作质量不混入上述客观分数。BOOKWORLD 风格 Pairwise 和真实 LLM
20 局回归使用独立报告，避免把主观偏好混入权威状态正确性。

## 2. 一键运行

```powershell
.\.venv\Scripts\python.exe -m evaluation
```

默认读取 [`evaluation/benchmark_cases.jsonl`](../evaluation/benchmark_cases.jsonl)，
并在 `data/evaluation/` 生成 JSON 明细和 Markdown 汇总。

生成固定路径的可版本化报告：

```powershell
.\.venv\Scripts\python.exe -m evaluation `
  --json evaluation/reports/deterministic-v1.json `
  --markdown evaluation/reports/deterministic-v1.md
```

模型价格必须由运行者明确提供，未提供时成本显示为“未配置单价”，不会猜价格：

```powershell
.\.venv\Scripts\python.exe -m evaluation `
  --currency USD `
  --input-per-million 2 `
  --cached-input-per-million 0.5 `
  --output-per-million 8
```

## 3. 固定案例

当前 v1 包含 9 个隔离案例：

| 类型 | 案例 |
|---|---|
| 核心路线 | Free、Script、玩家公开真相 |
| 玩家干预 | 销毁密信、携信离开 |
| 调度边界 | 2 回合强制结束 |
| 预期拒绝 | 无证据结盟、未知实体、来源角色认知越权 |

每次运行都从 `build_snapshot()` 创建新状态，不连接 Web 会话或生产 SQLite。
每个成功事件都重新验证版本链和 Patch，再从初始快照回放并比较终态哈希。

## 4. 指标口径

- `benchmark_pass_rate`：所有声明的状态、结局、工具链、失败码、版本和传播数量
  均与案例期望一致的比例。
- `core_event_completion_rate`：标记 `core_objective` 的案例中目标完成比例。
- `tool_success_rate`：成功 ToolResult /（全部调用 − 规则预期拒绝）。
- `expected_rejection_rate`：实际命中预期失败码 / 预期拒绝样本。
- `propagation_accuracy`：传播记录、目标认知与证据记录三方一致比例。
- `evidence_chain_completeness`：所有 `parent_evidence_ids` 可追溯的传播比例。
- `structural_character_consistency`：没有未知/死亡行动者等结构违规的调用比例；
  开放式人格忠实度由 Pairwise 评测补充。
- `P50/P95`：实际运行墙钟耗时；Trace 分阶段耗时另行聚合。
- Token：直接读取 OpenAI-compatible 响应的 `usage`，确定性运行严格为 0。

`objective_completion_rate` 会把“玩家销毁/截走密信”计为目标未完成，因此它低于
案例通过率是正确结果，不代表测试失败。

## 5. 消融设计

世界门禁采用 6 个生产验证器探针：不可用飞机概念、未知实体、缺少能力/
Affordance、认知越权、Action-Patch 因果越权和叙事无事件依据。

| 组 | 启用范围 |
|---|---|
| G0 | 仅提示词，不启用确定性门禁 |
| G1 | 世界概念与实体 |
| G2 | G1 + 能力/Affordance + 认知 + 因果授权 |
| G3 | G2 + 叙事事件依据 |

禁用门禁只做反事实判定，`authoritative_store_used=false`；不存在能被正式运行时
调用的“关闭安全校验”开关。

记忆消融在临时 SQLite 上对 50 条角色隔离中文查询比较：

- `no_memory`：返回空召回；
- `sqlite_fts5`：当前正式词法记忆基线。

## 7. 真实 LLM 20 局回归

运行（每局完成后写 checkpoint，可断点续跑）：

```powershell
.\.venv\Scripts\python.exe -m evaluation.real_runner `
  --resume `
  --output evaluation/reports/real-llm-v1.json `
  --markdown evaluation/reports/real-llm-v1.md
```

[`real-llm-v1.md`](../evaluation/reports/real-llm-v1.md) 的实测结果：

- 20/20 完整运行，18/20 目标成功，门禁通过；
- 14 个提交事件的回放、因果证据、叙事覆盖和结构化事件依据均为 100%；
- 两个飞机案例由本地世界规则前置拒绝，0 Token；
- 两条失败均为 `INVALID_ACTION`，报告保留输入、失败码和 usage；
- 45 次调用，49,255 Token，P50/P95 为 10.554s/16.469s；
- 未配置当前自定义网关价格，成本显示“未配置单价”。

这里的“结构化事件依据”表示叙事声明了已提交 `event_id`，且通过实体、世界概念、
说话者和认知边界检查；它不等价于对每个自然语言分句完成形式化语义证明。

## 8. BOOKWORLD 风格 Pairwise

当前使用 6 个真实 grounded 候选，对比确定性事件模板 sanity baseline。固定种子
交换左右顺序，Prompt 不含系统 ID；Free 评 Creativity，Script 评 Storyline
Quality，另有四个共同维度。

```powershell
.\.venv\Scripts\python.exe -m evaluation.pairwise `
  --samples evaluation/pairwise_samples_v1.jsonl `
  --json evaluation/reports/pairwise-v1.json `
  --markdown evaluation/reports/pairwise-v1.md `
  --human-packet evaluation/reports/pairwise-human-packet-v1.md
```

实测 6/6 Judge 成功，0 解析/调用失败，grounded LLM 叙事以 6–0 胜模板；
Judge 共 5,785 Token。该结果只证明评测管线和叙事层相对机械模板有效，不能写成
对强模型或同类系统的领先结论。

另增加同一 `qwen3.7-plus` 的 direct-prompt 强基线：两边获得相同权威时间、
敌对关系、玩家输入和事件上下文；基线不使用 `NarrativeOutput` Schema、event_id
引用或运行时一致性审查。最终配置中基线生成 6/6 通过核心事件启发式检查，
Pairwise 6/6 成功、0 解析/调用失败，结果为 3–3：

- NovelSim grounded Narrator 在三个取衣冲突场景胜出；
- direct-prompt 在三个简单步行场景胜出。

报告见 [`pairwise-strong-v1.md`](../evaluation/reports/pairwise-strong-v1.md)。
这说明结构化 Narrator 的优势集中在多角色冲突与状态变化，简单移动叙事没有表现出
主观优势。

`Left, Right, Right, Left, Left, Left`。对已有 Judge 报告做纯离线回填后：

- Cohen's κ 为 `0.667`；
- 新增 LLM 调用为 `0`；
- 唯一分歧为 `pair_pair_walk_02`。

报告见
[`pairwise-strong-calibrated-v1.md`](../evaluation/reports/pairwise-strong-calibrated-v1.md)。
这些标签反映评审偏好，不是客观标准答案；6 题样本不足以外推总体胜率。世界规则、
实体、因果和叙事依据仍由客观门禁单独判定。

A/B/C/D（LLM-only、混合、记忆、完整方案）长程真实模型消融保留为作品集后续，
当前不把 G0–G3、记忆消融或强基线结果冒充该实验。
