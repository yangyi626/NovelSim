# 主流技术调研与落地方案

> 调研日期：2026-07-26
> 目标：调研 AI 角色、长期记忆、世界状态、小说编译、评测与 3D 客户端的常见实现，并给出适合本项目当前阶段的落地顺序。

## 1. 结论

本项目不应在当前阶段整体迁移到某个大型 Agent 框架，也不应为了“技术完整”一次性引入 PostgreSQL、pgvector、Neo4j 和 Unity。更合适的路线是：

1. 保留现有 `WorldState + WorldEvent + TurnPipeline` 作为权威世界内核。
2. 把 Agent 记忆拆成短期工作记忆和长期可检索记忆。
3. 当前使用 SQLite FTS5 + Qdrant Local Mode 落地混合检索；SQLite 保存权威记录，Qdrant 只保存可重建向量。
4. 长期记忆属于可从事件重建的查询投影，不反向修改权威事件。
5. 下一阶段优先建立 20～60 回合长轨迹评测，再做反思记忆、全书编译和 Unity 客户端。

实施更新：第 2～4 项已完成首版；随后已补齐 Qdrant Local Mode、SQLite FTS5/Qdrant 混合重排、索引同步与重建、每角色容量治理和 20/60 回合确定性发布门禁。PostgreSQL + pgvector 后端代码继续保留，但当前开发与运行不依赖它。

## 2. 主流方案与项目映射

### 2.1 Agent：观察、计划、反思与分层记忆

[Generative Agents](https://arxiv.org/abs/2304.03442) 的代表性做法是保留完整经历流，按相关性动态召回，并从经历中形成高层反思；论文的消融实验显示观察、计划与反思都会影响角色行为可信度。[MemGPT](https://arxiv.org/abs/2310.08560) 则把有限上下文视作快速内存，把外部持久层视作慢速内存，通过分层调度扩展长期交互能力。

[LangGraph 的持久化设计](https://langchain-ai.github.io/langgraph/concepts/time-travel/?h=time+travel) 同样区分线程内短期状态与外部长时存储，并支持检查点、恢复和长期 Store。

对应到本项目：

| 主流抽象 | 本项目实现 |
|---|---|
| 短期工作记忆 | `CharacterPsyche.recent_perceptions`，只保留最近感知 |
| 情景长期记忆 | `character_memories`，按世界线和角色隔离 |
| 动态召回 | NPC 决策前根据本轮玩家输入检索 Top-K |
| 计划 | 已有 `goals + plans + CharacterScheduler` |
| 反思/语义记忆 | 数据类型与保护策略已预留，自动生成待真实 LLM 轨迹基线后增加 |

关键边界：召回结果只是角色的历史认知线索；如果记忆与当前 `WorldState` 冲突，决策必须以当前权威状态为准。

### 2.2 检索：SQLite FTS5 + Qdrant 混合召回

[SQLite FTS5](https://www.sqlite.org/fts5.html) 原生提供全文 `MATCH`、BM25 排序、摘要与高亮能力。它不需要额外服务，很适合当前单机 SQLite 阶段。为解决 `unicode61` 缺少中文分词的问题，本项目在写入时额外生成相邻双字词，并在召回后综合：

- Qdrant 语义相关性：80%
- SQLite 词法相关性：10%
- 记忆重要度：5%
- 时间新近性：5%

[Qdrant Python Client](https://github.com/qdrant/qdrant-client) 官方提供无需服务进程的 Local Mode，并允许同一套 API 后续切换到 Server/Cloud。项目将 Qdrant 视作派生索引：向量命中后必须按 `memory_id` 回查 SQLite，索引异常时自动降级为 FTS5。当前 Python 3.8 使用仍声明兼容的 [qdrant-client 1.11.3](https://pypi.org/project/qdrant-client/1.11.3/)。

上述权重不是拍脑袋设定：25 条记忆、50 个中文查询的真实 embedding 基准中，Hit@4 从 FTS5 的 84% 提升到 100%，MRR 从 0.805 提升到 0.957；纯语义反而下降到 98%，因此保留少量词法和记忆属性信号。

统一的“记录记忆 / 搜索记忆”接口保持不变，`TurnPipeline` 和 `CharacterAgent` 无需感知底层是 FTS5、Qdrant 还是未来的其他向量后端。

### 2.3 世界状态：选择性事件溯源 + 查询投影

[Microsoft 的 Event Sourcing 指南](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing) 将追加式事件作为事实记录，用事件重建状态或派生查询模型；同时强调该模式复杂，应只用于确实需要审计、回放和历史重建的领域。

本项目的选择性应用是合理的：

- `world_events`：不可变事实与版本链，是回放依据。
- `world_sessions.state_json`：当前快照，避免每次从头回放。
- `world_turns`：玩家可读剧情历史。
- `character_memories + FTS5 + Qdrant`：面向 Agent 的可重建查询投影。
- 创作者世界包：继续使用带 revision 的 JSON CRUD，不做事件溯源。

这避免了把复杂模式扩散到不需要历史回放的创作表单。

### 2.4 世界知识图谱与小说编译

[Neo4j GraphRAG 的知识图谱构建流程](https://neo4j.com/docs/neo4j-graphrag-python/current/user_guide_kg_builder.html) 包含文本切分、Schema 约束、实体/关系抽取、图清理和实体消歧；其 Entity Resolver 会合并指向同一真实对象的节点。

当前编译器已经具备同构的最小能力：章节/场景切分、受控 Schema 抽取、`EntityRegistry` 别名消歧、关系与事件校验。因此短期不引入 Neo4j。后续只有在以下需求明确出现时再考虑图数据库：

- 全书级跨章关系查询；
- 创作者后台大型关系图交互；
- 多跳问题成为高频查询；
- SQLite/JSON 的关系遍历出现可测量瓶颈。

### 2.5 Agent 评测：结果、步骤与轨迹分层

[LangSmith 的 Agent 评测指南](https://docs.langchain.com/oss/python/langchain/test/evals) 将 Agent 轨迹定义为消息与工具调用序列，可用确定性匹配或 LLM-as-judge 评估；[复杂 Agent 评测](https://docs.langchain.com/langsmith/evaluate-complex-agent) 进一步区分最终答案、单步行为和完整轨迹。

项目现有单元测试和短场景测试覆盖“能否正确执行”。当前已经增加第 1、2 项的确定性基础门禁，后续继续补 Agent 质量评分：

1. 20 回合固定剧本：版本连续、实体引用不泄漏、死亡角色不行动。
2. 60 回合随机动作：状态 Schema 始终合法，记忆量和提示长度受控。
3. NPC 轨迹评分：目标一致性、认知隔离、重复行为率、计划推进率。
4. Prompt/模型变更回归集：固定输入与允许的动作轨迹范围。

在这些基准建立前增加“反思记忆”会让行为变复杂，却难以判断是否真的变好。

### 2.6 Unity 客户端：表现层消费后端事实

[Unity 6 AI Navigation](https://docs.unity3d.com/ja/6000.0/Manual/com.unity.ai.navigation.html) 可在编辑期或运行期构建和使用 NavMesh，并处理动态障碍与连接；[Addressables](https://docs.unity3d.com/ja/Packages/com.unity.addressables%401.20/manual/index.html) 通过稳定地址异步加载本地或远程资产。

未来 Unity 应保持为表现与输入层：

- FastAPI 返回结构化事件、对白、动作和场景资源地址；
- Unity 根据资源地址加载角色/地点 Prefab；
- NavMesh 执行已经由规则层允许的移动；
- 动画和镜头只表现已提交事件，不直接改数据库；
- 断线后通过会话快照与事件版本恢复。

当前 Web 端仍是验证核心玩法的最低成本客户端，Unity 放在长期记忆和长轨迹稳定后启动。

## 3. 本轮落地

### 3.1 数据结构

新增 `character_memories`：

- `session_id`：隔离不同世界线；
- `character_id`：隔离不同角色认知；
- `source_event_id`：关联来源事件；
- `world_version`：记录发生时的世界版本；
- `memory_type`：当前为 `episodic`；
- `content`、`importance`、`created_at`；
- `(session_id, character_id, source_event_id, memory_type)` 唯一约束，保证重试幂等。

FTS5 是外部内容索引，通过 SQLite trigger 与主表同步；若运行环境不支持 FTS5，自动降级为 `LIKE` 检索，世界回合仍可继续。

### 3.2 回合数据流

```text
读取 WorldState
  → 按 session_id + character_id 检索相关长期记忆
  → 将每个 NPC 自己的 Top-K 注入 CharacterAgent
  → NPC 决策、规则校验、合并 Patch
  → 提交 WorldEvent + 新 WorldState
  → 将公开结果幂等投影为参与角色的情景记忆
```

检索或投影失败会降级并返回警告，不会把已经成功提交的世界回合伪装成失败。

### 3.3 已覆盖风险

- 中文“书店账本”等组合词可以召回；
- 不同世界线之间不可串记忆；
- 不同角色之间不可串记忆；
- 同一事件重复写入不会产生重复片段；
- 删除存档时记忆随外键级联删除；
- Agent 提示明确声明当前世界状态优先；
- Web 回合能够检索旧记忆并在提交后形成新记忆。
