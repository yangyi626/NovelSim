# NovelSim 必须补充内容

## 1. 当前基础与补充目标

NovelSim 后端已经具备以下主体能力：

- 4 个独立 NPC。
- 受限工具调用。
- 权威世界引擎。
- NPC 知识隔离。
- 长期记忆。
- 状态存档与回放。
- Unity 服务器权威竖切片。

下一阶段不再扩展更多后端概念或增加 NPC 数量，重点是把现有能力组织成一个招聘方可以直接验证的完整游戏闭环：

> 可玩、可控、可观测、可评测、可复现。

## 2. P0：完成一个端到端可玩竖切片

### 2.1 场景规模

制作一个可在 10–15 分钟内体验完毕的小型场景，使用现有 4 个 NPC 即可：

| NPC | 主要职责 | 需要展示的能力 |
| --- | --- | --- |
| 委托人 | 发布任务并掌握私有线索 | 任务状态、知识边界、承诺记忆 |
| 商人 | 交易物品和情报 | 库存、货币、关系条件、原子交易 |
| 守卫 | 根据证据采取行动 | 信息传播、规则判断、动态决策 |
| 敌对角色 | 欺骗、逃跑或战斗 | 目标规划、冲突处理、状态变化 |

### 2.2 最小闭环流程

必须让以下能力出现在同一条可玩流程中：

1. 玩家从委托人处接受任务。
2. 玩家通过对话、观察或交易获得线索。
3. 私有信息只能通过合法的感知或交流事件传播。
4. NPC 根据自身目标、关系、记忆和已知事实自主决定下一步行为。
5. 至少发生一次有效交易，正确更新货币、库存及相关事件。
6. 至少发生一次战斗或敌对冲突，权威世界引擎负责校验并提交结果。
7. 任务状态根据世界事实推进、失败或完成，不能由 LLM 直接改写。
8. NPC 对关键事件形成长期记忆，并在后续决策或对话中正确使用。
9. 任意关键节点可以存档、恢复并重放，最终状态可验证。

### 2.3 必须覆盖的动态异常

场景不能只支持预设的理想路径，至少覆盖以下异常：

- 交易过程中 NPC 或玩家被攻击。
- 任务目标提前死亡或离开场景。
- 任务物品被其他 NPC 取走或已经售出。
- 两个角色同时尝试购买最后一件物品。
- NPC 获得与已有记忆冲突的新信息。
- 玩家反复提交同一动作或重复领取奖励。
- LLM 输出非法动作、缺失字段或不存在的实体 ID。

异常发生后，系统应拒绝非法提交、产生明确原因，并让 NPC 重新规划或安全降级。

### 2.4 Unity 最小可视化要求

不追求美术质量，但必须能直接观察行为闭环：

- 4 个 NPC 均有可区分的角色、位置和当前状态。
- 支持基本移动、对话、交易、任务和战斗结果展示。
- 对话气泡或事件面板能够显示角色公开表达。
- 世界中的物品、货币、生命值和任务状态变化可见。
- 能暂停、单步执行、继续、存档和加载。
- 能从 Unity 打开对应 Agent Trace 或调试信息。

### 2.5 竖切片完成标准

- [ ] 一次完整流程可以从接取任务运行至成功或失败结局。
- [ ] 4 个 NPC 均至少执行一次自主决策和受限工具调用。
- [ ] 交易、任务、战斗和信息传播在同一局内产生可观察影响。
- [ ] 客户端只能发送意图或动作请求，不能直接修改权威状态。
- [ ] 非法动作不会污染库存、关系、生命值或任务状态。
- [ ] 可从至少 3 个关键检查点恢复并继续运行。
- [ ] 提供固定随机种子下的可重复演示路径。

## 3. P0：建立分层评测体系

现有回归测试主要证明确定性规则正确，还需要补充 Agent 行为质量和游戏体验评测。

### 3.1 世界引擎层

必须记录：

- 状态不变量违反次数。
- 非法状态提交次数及拒绝原因。
- 交易和战斗的原子提交正确率。
- 重复请求的幂等处理结果。
- 并发修改冲突次数及处理结果。
- 存档恢复后的状态哈希一致率。
- 相同事件日志重放后的最终状态一致率。

建议初始验收标准：

- 确定性规则用例中的状态不变量违反次数为 0。
- 存档恢复和事件重放的状态哈希一致率为 100%。
- 重复请求不得产生重复扣款、重复物品或重复奖励。

### 3.2 Agent 行为层

必须记录：

- 任务成功率。
- 合法工具调用率和首次调用成功率。
- 无效实体、无效参数和越权调用比例。
- NPC 知识泄漏率。
- 记忆检索命中率及证据引用正确率。
- 长轨迹目标保持率。
- 环境变化或计划中断后的恢复成功率。
- 多 NPC 协作或冲突场景成功率。
- 单步决策平均延迟、P95 延迟和 Token 消耗。
- 单次完整游戏会话的模型调用成本。

知识泄漏测试必须区分：

1. NPC 初始私有知识。
2. NPC 实际感知到的事件。
3. 通过合法对话获得的信息。
4. 仅存在于全局世界状态、但该 NPC 不应知道的信息。

在边界明确的确定性用例中，第 4 类信息的泄漏次数应为 0。

### 3.3 游戏体验层

至少建立一组人工或 LLM-as-Judge 辅助评测，检查：

- 角色行为是否符合人设、目标和当前关系。
- 行为是否有可追溯的感知、记忆或规则证据。
- 长轨迹中是否产生事实矛盾。
- NPC 是否无意义重复对话或动作。
- 行为是否具有合理多样性，而不是所有 NPC 使用同一策略。
- 玩家是否需要人工干预才能完成正常流程。

LLM-as-Judge 只能作为辅助指标，必须抽样进行人工复核，并保存评分依据和完整轨迹。

### 3.4 评测集规模与组织

建议建立三类评测集：

- **确定性规则集**：覆盖交易、任务、战斗、权限、并发和回放。
- **固定场景集**：使用固定初始状态和随机种子，比较不同版本。
- **扰动场景集**：随机改变角色关系、物品位置、事件顺序和模型输出错误。

每个用例至少保存：

- 初始世界状态。
- 每个 NPC 的可见知识。
- 任务目标和成功条件。
- 随机种子与模型配置。
- 完整事件日志和工具调用。
- 预期不变量。
- 最终指标和失败类型。

## 4. P0：完成基线与消融实验

至少比较以下版本：

| 实验版本 | 目的 |
| --- | --- |
| 完整系统 | 作为最终结果 |
| 移除长期记忆 | 验证长期记忆对长轨迹行为的贡献 |
| 移除知识隔离 | 量化信息泄漏和剧情一致性变化 |
| 仅关键词检索 | 与关键词和向量混合检索比较 |
| 移除反思或重规划 | 验证中断恢复和目标保持能力 |
| LLM 直接提出状态修改 | 离线展示权威引擎对非法状态的抑制作用 |

所有版本必须使用相同的场景集、随机种子、模型参数和运行预算。

最终至少输出一张结果表，包含：

- 任务成功率。
- 知识泄漏率。
- 事实矛盾率。
- 非法动作率。
- 中断恢复率。
- 回放一致率。
- 平均延迟、P95 延迟和成本。

## 5. P0：补齐可观测性与故障恢复

### 5.1 Trace 与调试面板

每个 NPC 的一次决策必须能够追踪以下信息：

- 当前目标和子目标。
- 当前可见事实与私有信念。
- 检索到的记忆及证据 ID。
- 结构化决策摘要。
- 提议调用的工具和参数。
- 规则校验结果及拒绝原因。
- 提交前后的世界状态 Diff。
- 模型、工具和存储调用耗时。
- Token 消耗、重试次数和最终状态。

不记录或展示模型隐藏思维链；使用结构化决策摘要、证据引用和规则判定保证可审计性。

### 5.2 必须处理的故障

- LLM 超时、限流和网络错误。
- 空输出、非法 JSON 和 Schema 不匹配。
- 工具执行超时或部分失败。
- 重复工具调用和重复事件投递。
- 两个 NPC 同时修改同一实体。
- 记忆服务或向量数据库不可用。
- 状态提交成功但客户端响应丢失。
- 回档后残留异步任务、缓存或旧版本事件继续执行。

每类故障都应定义：

1. 检测方式。
2. 重试或降级策略。
3. 是否允许继续提交状态。
4. 玩家和开发者可见的错误信息。
5. 对应的自动化测试。

## 6. P0：形成可交付作品

项目最终必须具备以下材料：

- [ ] 可运行的 Unity 竖切片。
- [ ] 2–3 分钟演示视频。
- [ ] 一张系统架构图，明确 Unity、Agent Runtime、记忆层、规则校验层和权威世界状态之间的关系。
- [ ] 一张基线与消融实验结果表。
- [ ] 一个典型成功 Trace 和一个故障恢复 Trace。
- [ ] 可复现的启动说明、模型配置和测试命令。
- [ ] 固定随机种子的演示脚本。
- [ ] README 中明确个人完成的部分、系统边界和已知限制。

## 7. 推荐实施顺序

### 阶段一：打通可玩闭环

- [ ] 固定 4 个 NPC、地图和任务剧情。
- [ ] 接通交易、任务和战斗的最小表现层。
- [ ] 接通 Unity 与权威世界状态的完整同步。
- [ ] 完成成功、失败和异常中断路径。

### 阶段二：建立评测与消融

- [ ] 把现有回归测试整理为确定性规则集。
- [ ] 新增长轨迹、知识泄漏和中断恢复评测。
- [ ] 固定模型、场景和随机种子。
- [ ] 运行完整系统及各消融版本。
- [ ] 生成汇总结果表和失败分类。

### 阶段三：补齐工程可靠性

- [ ] 接入统一 Trace、状态 Diff 和成本统计。
- [ ] 完成幂等、并发冲突、超时和降级处理。
- [ ] 验证存档恢复与事件重放的一致性。

### 阶段四：整理展示材料

- [ ] 录制演示视频。
- [ ] 绘制架构图和关键时序图。
- [ ] 精简 README，并提供一键运行路径。
- [ ] 将最终指标写入简历项目描述。

## 8. 当前阶段明确不做

- 不增加第五或第六个 NPC。
- 不追求高质量角色、美术资产和复杂动画。
- 不把交易、任务或战斗扩展成完整商业游戏系统。
- 不立即从 Unity 重写到 Unreal Engine。
- 不在评测体系完成前训练专用模型。
- 不优先开发完整多人联网功能。
