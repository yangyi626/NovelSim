**核心 AI 引擎 + 角色 Agent + 小说编译器 + 可持久化 Web 试玩闭环已经完成并验证，创作者后台已具备账户分权和审计，生产数据架构已形成。** 玩家可用自然语言改变世界并触发 NPC 自主反应；NPC 会召回自己的相关经历，并从多次经历中形成带证据链、可被后续认知纠正的反思。新增的显式 Agent 执行状态机把 LLM 高层决策限制为严格 JSON Schema 工具调用，所有工具效果必须经过权限、实体、时空、认知与 `StatePatch` 校验后才能原子提交。当前正式开发组合是 SQLite 权威状态/事件/记忆/账户/任务 + Qdrant Local Mode 派生向量索引，不需要 Docker 或独立数据库服务；全书编译由独立 Worker 通过 SQLite 租约执行，PostgreSQL + pgvector 后端代码继续保留。项目已提供 Windows 一键启动和跨平台进程管理入口，并在 Pull Request 与 `main` 推送时执行确定性 CI 门禁。

## 1. 已完成的核心能力

### 1.1 世界数据标准（world_schema）

对应 plan 第三节。定义了整个系统的"南北极"数据契约：

| Schema | 作用 | 状态 |
|---|---|---|
| `Action` | 玩家/NPC 想做什么（含 ActionType 白名单） | ✅ |
| `WorldState` | 当前客观世界事实（权威状态快照） | ✅ |
| `StatePatch` | 本轮允许的状态变化（含 Operation 白名单） | ✅ |
| `WorldEvent` | 已正式发生的不可变事实（事件溯源基石） | ✅ |
| `CharacterBelief` | 角色认知（含 keywords 支持中文泄漏检测） | ✅ |
| `CharacterRelation` | 多维关系（affection/trust/fear/hostility/respect/debt） | ✅ |
| `NarrativeOutput` / `DialogueLine` | 表现层数据契约（旁白/对白/系统提示） | ✅ |
| `Operation` | 状态操作（13 种 op，`extra="forbid"` 严格受控） | ✅ |
| `Rule` / `WorldRule` / `PlotArc` / `Character` / `Item` / `Location` | 世界实体 | ✅ |

设计要点：
- 所有实体 `extra="allow"`，小说特有字段（如 `cultivation_level`）放 `attrs` 自由口袋。
- `Operation` 严格 `extra="forbid"`——这是"LLM 可提议、但不可越权改库"的权限边界。

### 1.4 完整 Turn Pipeline

对应 plan 第八节。`engine/turn.py` 把上述组件串成一条完整游戏回合：

```
用户自然语言
   ↓ ActionParser (LLM)
Action
   ↓ RuleEngine (规则校验) ──┐
合法 Action                  │ 三层安全防线
   ↓ TransitionProposer (LLM)│ - Pydantic Schema
StatePatch                   │ - patch_validator
   ↓ CharacterScheduler ★   │ - apply_patch 兜底
NPC 自主反应叠加              │
   ↓ commit_event            │
WorldEvent (version+1)       │ - 死人不说话
   ↓ NarrativeGenerator (LLM)│ - 认知不泄漏
NarrativeOutput              │
   ↓
玩家看到的: 旁白 + 对白 + 系统提示 (+ NPC 的对白/动作)
```

★ 角色调度默认关闭 (`use_npc_agents=False`)，显式开启后玩家行动提交前会唤醒相关 NPC。

### 1.5 角色 Agent（plan 第十步）

让 NPC 有自主行动，而不是只对玩家行动做"反应式 patch"。这是世界"活起来"的关键。

| 模块 | 作用 |
|---|---|
| `world_schema.CharacterPsyche` | 角色内在状态：人格 traits / 目标 goals / 计划 plans / 情绪 emotion / 短期记忆 |
| `world_schema.AgentDecision` | 一次决策产物：候选动作 + 预期 patch + 情绪/感知更新 |
| `engine.CharacterAgent` | 单个 NPC 的决策单元：读取**自己可见的事实**（认知不越权）→ LLM 生成候选动作 → patch_validator 兜底 |
| `engine.CharacterScheduler` | 事件驱动调度：选哪些 NPC 行动（被波及/在场/有计划者）→ 合并 patch |

决策流程（plan 第八节）：
```
读取角色可见事实 (基于 beliefs)
→ 检索角色相关记忆 (recent_perceptions)
→ 生成候选动作 (LLM，产出 AgentDecision)
→ 规则过滤 + patch_validator 兜底
→ 选择动作 (可按兵不动)
→ 产出 NPC Action + 候选 StatePatch
```

华容巷 psyche 初始化（`examples/huarong_lane/scenario.py.build_psyches`）：
- **夜轻歌**（玩家宿主，is_player=True，永不被自动调度）：目标"反客为主洗刷废柴名"，计划"先立威→查真相→夺主导权"
- **夜清清**（自主 NPC）：人格"阴毒/隐忍/心机深"，目标"除掉夜轻歌上位嫁小王爷"，计划"陷害→联合管家→取代嫡位"
- **林管家**（自主 NPC）：人格"圆滑/趋炎附势/与清清有私情"，目标"保全夜清清维护自身地位"

#### 长期记忆的第二层：反思/语义记忆

- 情景记忆继续记录 NPC 亲历的具体事件。
- 每 5 个世界版本检查一次；至少 3 条未处理经历才调用低温 LLM。
- 每条反思至少引用 2 个事件 ID，并保存稳定 `fact_id`、belief 与 confidence。
- 相同主张使用稳定来源 ID 幂等更新，并合并新增证据，不堆积同义记忆。
- 写入前拒绝与当前权威认知相反的候选；召回前再次过滤后来已经过期的反思。
- 反思完整记录保存在 SQLite，Qdrant 只同步可重建向量与过滤元数据。
- 首次空结果会进行一次受约束的二次审视；真实模型已成功从“折断刀刃 + 护卫畏惧”提炼“夜轻歌可能隐藏实力”。
- 独立语义审查器再次检查证据蕴含、矛盾、覆盖率和过度推断；默认总分门槛 0.72，失败关闭。

详细设计与运维见 [`反思与语义记忆.md`](反思与语义记忆.md)。

### 1.6 小说世界编译器（plan 第十二步）

用 LLM 把整本 TXT 自动编译成 WorldPackage，不再手工造。

| 模块 | 作用 | 是否 LLM |
|---|---|---|
| `compiler/text_loader.py` | TXT 导入（自动编码探测）→ 文本清洗 → 章节切分 → 场景切分（启发式） | 否（确定性） |
| `compiler/extractors.py` | `EntityExtractor`：场景文本 → 实体/关系/事件/规则/角色状态/伏笔/目标演化（带 evidence + confidence） | 是 |
| `compiler/scene_compiler.py` | `EntityRegistry` + `SceneCompiler` + `ChapterCompiler` + `VolumeCompiler` + `PackageBuilder` | 否 |
| `compiler/book_compiler.py` | 全书级身份消歧、多时间线、章节/卷/全书三级快照与评分事件投影 | 否 |
| `compiler/job_store.py` / `job_runner.py` / `worker.py` | SQLite 租约队列、独立 Worker、逐章进度/场景缓存/快照，暂停继续取消、重启恢复、自动质量审核 | 编排层调用 LLM |
| `compiler/cli.py` | CLI 入口：`python -m compiler.cli novels/xxx.txt -c 1 2 -o worlds/pkg.json` | 是 |

编译流水线：
```
TXT → 编码探测 → 清洗 → 章节切分 → 场景切分
   → EntityExtractor (LLM)：实体/关系/事件/规则/跨章演化
   → EntityRegistry：alias 消歧 (跨场景/章节 alias → 稳定 id)
   → VolumeCompiler：角色章节状态 + 伏笔生命周期 + 目标演化
   → 事件草稿 op → 严格 Operation (patch_validator 校验)
   → 累积进 WorldState
   → 发布 WorldPackage (JSON + 可直接 build_snapshot)
```

每条抽取结果带 `evidence`（原文片段）+ `confidence`（0-1），便于人工审核与回归测试（plan 第十五步）。

当前完成 plan 第十二步的 **A（单场景）+ B（单章节）+ C（单卷跨章节演化）+ D（全书全局消歧、多时间线、分层快照）**。全书编译通过 SQLite 任务运行，支持场景缓存、暂停、继续、取消和服务重启后的断点恢复。

当前 API：

- `POST /api/start`：从指定 `package_id` 创建干净世界快照并返回会话 ID。

- `POST /api/turn`：运行完整 Turn Pipeline，成功后把新状态写回当前会话。
- `GET /api/saves`：列出全部世界线存档及其版本、更新时间。
- `PATCH /api/saves/<id>`：修改存档名。
- `GET /api/saves/<id>/export`：下载包含状态、事件和剧情历史的完整 JSON 备份。
- `POST /api/saves/import`：校验并原子导入完整备份，以新会话 ID 创建世界线。
- `DELETE /api/saves/<id>`：删除世界线及其事件和剧情历史。
- `GET /api/state?session=<id>`：查询会话状态，用于调试。
- `GET /api/events?session=<id>`：按版本顺序查询事件日志，用于审计与回放。
- `GET /api/creator/packages` / `GET /api/creator/packages/<id>`：列出/读取世界包。
- `POST /api/creator/packages/<id>/clone`：把内置或已有世界包另存为新版本。
- `POST /api/creator/packages/validate`：执行 Schema 与跨实体引用校验。
- `PUT /api/creator/packages/<id>`：使用修订号冲突保护保存世界包。
- `GET /api/creator/packages/<id>/revisions`：读取不可变修订历史。
- `GET /api/creator/packages/<id>/diff`：比较两个修订的结构化字段差异。
- `POST /api/creator/packages/<id>/review`：执行提交审核、批准、驳回与发布状态转换。
- `GET /`：托管 Vite 构建出的单页应用。

### 1.9 创作者后台 MVP+（plan 第十三步）

本阶段已形成“模板创作 → 校验 → 发布本地版本 → 新开局试玩”的最小闭环：

- `engine/world_packages.py`：统一管理内置只读包与 `worlds/*.json` 创作者包。
- 内置包不可原地修改，必须克隆为 `<package_id>_vN`，避免破坏回归基准。
- 保存时校验 `WorldState` Schema、默认角色、当前场景、角色/物品/地点引用、地点层级循环、物品双重归属、关系端点、认知与心理角色、重复认知事实、认知来源/关键词、Agent 目标/计划引用、规则 ID。
- 使用 `revision` 乐观锁阻止旧编辑页面覆盖新修订。
- 每次保存和审核操作写入 `worlds/.history/` 不可变修订，可查看最近版本并生成结构化差异。
- 审核状态机为 `draft → pending_review → approved → published`，支持驳回、撤回和发布后开启新修订。
- 兼容 `compiler.PackageBuilder` 的既有输出格式，可直接载入创作台补充场景名、介入锚点和默认玩家角色。
- 创作台提供总览、角色、角色心理、角色认知、地点、物品、关系、世界规则、剧情线和高级 JSON 十个编辑区。
- 地点编辑支持父子层级、访问权限和扩展属性；删除前检查初始场景、角色、物品及子地点引用。
- 物品编辑支持角色持有/地点放置、数量、唯一性、可交互性和扩展属性。
- 角色心理编辑支持人格、情绪、玩家宿主标记、短期记忆、目标优先级与计划步骤。
- 角色认知编辑支持五级事实判断、可信度、信息来源、来源事件和中文关键词；用于约束 NPC 决策与对白认知泄漏。
- “保存并试玩”会保存当前修订，再调用 `/api/start` 从该模板创建独立 SQLite 世界线。
- 人物关系编辑区包含 SVG 有向关系图，审核面板展示状态、修订历史和前后差异。
- 全书编译页展示任务和逐章进度、缓存命中、章节/卷/全书快照、质量评分，并提供暂停、继续和取消。
- 编译完成后自动执行真实 LLM 长轨迹门禁；通过后进入 `pending_review`，失败或异常时保留草稿供修正。
- 创作者账户使用 Bearer token；`creator`、`reviewer`、`publisher`、`admin` 分离编辑、审核、发布和用户管理权限。
- 关键创作、编译、审核、发布和权限拒绝操作写入 SQLite 审计事件；自动质量门禁以 `system` 身份记录。
- 核心 API 已冻结为 `1.0.0`，契约清单由自动测试防止路径和方法被意外删除。

## 2. 安全边界（已确立并测试）

这是整个系统能长期稳定运行的根基，对应 plan 第七节"LLM 只开放受控权限"：

```
LLM 可以提议 Action
LLM 可以提议 StatePatch
LLM 可以生成表现文本

LLM 不可以直接执行 SQL
LLM 不可以绕过规则
LLM 不可以直接修改权威状态
```

具体落地的三层防线：

| 层 | 机制 | 拦截案例 |
|---|---|---|
| 第1层 | Pydantic Schema（`Operation extra="forbid"`） | LLM 输出非法字段被拒 |
| 第2层 | `patch_validator`（应用前校验） | 编造 item_id、`delta=5.0` 越界、`dimension="love"` 非法维度 |
| 第3层 | `apply_patch` 内置校验（应用时兜底） | 实体不存在、数值超界 |
| 表现层 | `narrative_consistency` | 死人说话、对白泄露未知事实 |
| 角色层 | `CharacterAgent` 认知隔离 + psyche 校验 | NPC 只依据自己 beliefs 行动；`update_psyche` 不可作用于玩家宿主；死人/玩家不调度 |
| 编译层 | `draft_ops_to_patch` + `patch_validator` | 编译抽取的事件草稿 op 引用未知实体时被丢弃，不污染 WorldState |

实测全部防线有效，有对应测试覆盖。

## 5. 真实效果示例

用户输入 → 系统完整产出（qwen3.6-plus 真实运行）：

**输入**：`"我冷冷地盯着夜清清，命令她把身上的外衫脱下来交给我，声音里没有一丝温度"`

**系统产出**：
- Action：`speak`（命令），目标夜清清
- 状态变化（4 条，每条带理由）：
  - `transfer_item`：夜清清迫于嫡庶尊卑与威压脱下外衫
  - `update_relation`：夜清清敌意加深（屈辱）
  - `update_relation`：夜清清对夜轻歌**忌惮加深**（打破"废柴"认知）
  - `set_attr`：衣衫不整状态缓解
- 旁白：完整古风小说段落（晨风/青石板/枯叶环境 + 屈辱/惊疑/忌惮心理 + 呼应嫡庶尊卑设定）
- 对白：夜轻歌（冰冷、不容置喙）"把外衫脱了，给我。" / 夜清清（隐忍、微颤）"……是，姐姐。"
- 系统提示：获得外衫 / 敌意上升 / 忌惮加深 / 身体状态更新

亮点：LLM 自主推演出**双向关系变化**（敌意 + 忌惮），"忌惮"完全是从"废柴嫡姐变强"语境读出来的，硬编码无法做到。

### 5.1 角色 Agent 自主行动（qwen3.6-plus 真实运行）

把夜清清从"被动受 patch"变成"主动决策者"。在受辱锚点唤醒她：

**夜清清的决策**：
- decided = `True`
- action：`observe`（隐于人群侧后方，冷眼旁观夜轻歌应对受辱局面的反应，暗中确认通奸陷害的局是否已按预期发酵）
- 情绪：冷静算计（强度 0.65）
- 感知：*"华容巷风波正起，夜轻歌此刻的狼狈正是推她入通奸死局的最佳跳板"*

亮点：夜清清没有莽撞反击，而是**根据自己"心机深/隐忍"的人设和"陷害上位"的目标**，选择冷眼旁观、确认阴谋是否得逞——这是从她的人格 + 目标 + 认知里推出来的，完全符合原著人设，而不是模板反应。调度器还能同时唤醒林管家（盘算重新站队）。

### 5.2 小说编译器：TXT → WorldPackage（qwen3.6-plus 真实运行）

`python -m compiler.cli novels/第一狂妃：废柴三小姐.txt -c 1` 编译第 1 章，LLM 自主抽出：

- **4 个角色**：夜轻歌（别名 三小姐/无名，标签 嫡系/废柴/丑女/佣兵）、夜清清（庶妹）、林管家、小王爷（未婚夫）
- **3 条关系**：夜清清→夜轻歌（庶妹-嫡姐）、夜轻歌→小王爷（未婚夫妻）
- **3 条世界规则**：家族名誉高于个人、丹田破碎者无法修炼、世家婚约有社会约束力

亮点：这与手工版 `examples/huarong_lane` **同构**——证明编译器确实能替代手工建模。实体消歧把"三小姐"和"夜轻歌"自动合并成同一角色（alias → 稳定 id），跨场景一致。

## 8. 过程中解决的环境问题

记录踩过的坑，便于环境复现：

1. **pip 21.1.1 SSL bug**：`check_hostname requires server_hostname`。绕过方案：用 `urllib` 直接下 wheel 到 `.deps/`，再 `pip install --no-index --find-links=.deps` 离线装。
2. **Python 3.8 依赖版本**：pydantic 锁 1.x、numpy 1.24、pandas 1.5、openai 0.28——这些是最后兼容 3.8 的版本组合。
3. **系统代理 TLS 失败**：Clash 代理 `127.0.0.1:7897` 的 TLS 握手挂掉（`SSLEOFError`），requests 自动读它。解决：脚本开头设 `NO_PROXY=*` 直连。`.env` 里也配了。
4. **openai 新旧 SDK 混用**：原 `api_test.py` 用了新版（≥1.0）的 `openai.chat.completions` 风格 + 旧版全局变量设置，不兼容。统一用 0.28 的 `ChatCompletion.create`。

依赖 wheel 缓存在 `.deps/`（已 gitignore），环境迁移时可直接复用。
