# 真实 LLM 长轨迹评分

## 目的

确定性轨迹门禁负责发现版本链断裂、未知实体、死亡角色行动和非法 Patch；真实 LLM 评分负责判断难以用规则表达的叙事质量：

- 因果是否连续；
- 角色是否符合人格与认知；
- 长期目标是否推进或合理调整；
- 叙事是否忠于结构化状态；
- 是否出现重复台词和原地循环。

两者是互补关系。LLM 高分不能覆盖确定性门禁失败。

## 分块与聚合

`LLMTrajectoryEvaluator` 默认每 12 个事件形成一个窗口：

```text
60 个事件
  → 5 个连续窗口独立评分
  → 聚合模型读取 5 份评分与问题
  → 生成总体五维评分
  → 总分和单维最低分共同决定是否通过
```

默认门槛：

- 总分不低于 `0.72`；
- 任意单维不低于 `0.60`；
- 聚合报告不得包含严重度为 `high`、`critical` 或 `error` 的阻断问题。

这种 Map/Reduce 方式避免把完整长局一次性塞入模型而丢失中段证据。低分窗口不能在聚合阶段被静默忽略，重复问题会提高严重度。

## 使用

对现有 SQLite 世界线执行真实评分：

```powershell
.venv\Scripts\python.exe -m engine.evaluate_llm_trajectory `
  --session <session_id>
```

可调整：

```powershell
.venv\Scripts\python.exe -m engine.evaluate_llm_trajectory `
  --session <session_id> `
  --chunk-size 10 `
  --threshold 0.75 `
  --minimum-dimension 0.65
```

返回码 `0` 表示通过，`2` 表示评分完成但未达到发布门槛。模型调用或结构解析失败会直接报错，不会把不完整结果当作通过。

## 当前验证

- 25 事件确定性测试验证了 3 个窗口加 1 次聚合调用。
- 单维低于门槛时发布门禁失败。
- 即使总分和全部单维达标，高严重度问题仍会阻止自动进入审核流。
- 真实模型已完成 20 事件、2 个窗口加总体聚合的烟测。
- 编译任务已在独立 Worker 中运行评分，Web 请求不会被长轨迹评测阻塞。
