# 真实全书编译生产演练

## 目标

本里程碑不再把“全书任务能够排队”等同于“全书已经验证”。生产演练分成三档，
先用可控成本验证 Worker、SQLite 租约、断点恢复、场景缓存、质量门禁和审核流，
再逐步扩大到真实全书：

| 档位 | 每本书章节 | 用途 |
|---|---:|---|
| `quick` | 20 | 日常真实 LLM 演练 |
| `stress` | 200 | 长时间运行、限流和恢复演练 |
| `full` | 全书 | 正式全书基准，必须显式确认 |

## 预算保护

`compiler_jobs` 持久化：

- `max_llm_calls`：任务硬调用上限；
- `llm_calls_used`：已经占用的真实调用次数。

抽取器和长轨迹质量评分器在每次请求模型前通过 SQLite 原子占用额度。额度不会因
Worker 重启或任务恢复而归零；耗尽时任务转为 `paused`，释放 Worker，并保留已完成
章节、场景缓存和分层快照。

创作者后台新建任务默认限制 100 次，可在任务详情查看已用次数和剩余额度。

## 执行前估算

```powershell
.venv\Scripts\python.exe -m compiler.benchmark estimate --profile quick
.venv\Scripts\python.exe -m compiler.benchmark estimate --profile stress
.venv\Scripts\python.exe -m compiler.benchmark estimate --profile full
```

基于两本真实小说的场景结构和此前首章烟测平均每次 185.793 秒，当前估算为：

| 档位 | 章节 | 场景/基础抽取 | 预计串行耗时 |
|---|---:|---:|---:|
| quick | 40 | 49 | 2.529 小时 |
| stress | 400 | 555 | 28.643 小时 |
| full | 6,163 | 9,679 | 499.525 小时 |

费用与模型服务商的 token 单价有关。可用 `--cost-per-call-cny` 输入一次调用的
校准均价；未提供时报告明确标记 `requires_rate`，不伪造费用数字。

## 安全排队

```powershell
# 默认 quick；自动按每本书真实场景数计算调用上限
.venv\Scripts\python.exe -m compiler.benchmark `
  --db data/benchmarks/production-drill.sqlite3 `
  enqueue --profile quick

# 全书必须先估算并显式确认
.venv\Scripts\python.exe -m compiler.benchmark `
  --db data/benchmarks/production-drill.sqlite3 `
  enqueue --profile full --confirm-fullbook
```

运行 Worker：

```powershell
.venv\Scripts\python.exe -m compiler.worker `
  --db data/benchmarks/production-drill.sqlite3 `
  --worlds data/benchmarks/worlds `
  --auth-db data/benchmarks/auth.sqlite3
```

生成 JSON 与 Markdown 报告：

```powershell
.venv\Scripts\python.exe -m compiler.benchmark `
  --db data/benchmarks/production-drill.sqlite3 `
  report --run data/benchmarks/<run-id>.json
```

报告包括任务状态、章节进度、Worker 尝试次数、LLM 调用预算、缓存命中率、
吞吐量、耗时、质量分和审核产物。
