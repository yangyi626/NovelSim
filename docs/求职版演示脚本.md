# NovelSim 求职版演示脚本

本脚本分成两份：一份用于录制 2–3 分钟无剪辑核心视频，一份用于 10–15 分钟
面试现场演示。所有口播都只使用已经实测的数据。

## 1. 录制前验收

录屏前不要临时改代码。先在 PowerShell 中执行：

```powershell
.\start.cmd
.\.venv\Scripts\python.exe -m evaluation `
  --json evaluation\reports\deterministic-v1.json `
  --markdown evaluation\reports\deterministic-v1.md

Set-Location unity\NovelSim3D
.\build-windows.ps1
.\run-windows-smoke.ps1
.\record-showcase.ps1 -DurationSeconds 130
```

确认：

- `http://127.0.0.1:8000/api/health` 返回健康；
- Windows 包能恢复同一个 `session_id` 和世界版本；
- F1 面板能看到版本、最近事件或连接状态；
- 浏览器自然语言输入框可用；
- 关闭桌面通知、API Key 和本地路径等隐私内容；
- 自动证据版为窗口实际像素 1024×576、约 30 FPS、无鼠标；若另录人工口播版，
  建议使用 1920×1080、30 FPS。

若真实模型服务不可用，停止录制，不把离线模板冒充真实模型结果。确定性门禁演示
可以离线运行，但要在画面上明确标注。

## 2. 2–3 分钟无剪辑视频分镜

目标时长 2 分 35 秒，全程一次录制，允许窗口切换，不做跳切。

| 时间 | 画面与操作 | 口播 |
|---|---|---|
| 00:00–00:12 | README 首屏，项目名和一句话目标 | “NovelSim 解决的是 LLM 能提出游戏行动、但不能直接成为世界事实的问题。” |
| 00:12–00:32 | 打开 Windows x64 包，WASD 接近 NPC | “Unity 负责移动和表现，SQLite 中的服务端状态才是权威事实。” |
| 00:32–00:58 | 按 E 触发真实交互；展示 NPC 转向、移动、对话或物品变化 | “玩家输入先变成候选 Action，再通过实体、能力、时空、认知和因果门禁，成功后才提交事件。” |
| 00:58–01:20 | F1 打开调试面板，指向世界版本、事件游标和命令序列 | “Unity 只消费带 sequence 和 command_id 的已提交事件，断线后从游标继续，不反向修改世界。” |
| 01:20–01:45 | 切到浏览器，输入“夜轻歌开飞机飞走了” | “这是古代世界没有注册的技术概念。系统返回 WORLD_CONCEPT_UNAVAILABLE，版本不增加，也没有飞行动画。” |
| 01:45–02:08 | 打开确定性报告中的 G0–G3 表和真实 LLM 报告 | “仅提示词会放过 6 个违规探针；完整门禁降到 0。真实模型固定回归 20 局完整运行，18 局目标成功。” |
| 02:08–02:28 | 展示密信因果图或运行原创密信场景 | “守卫观察密信后，证据逐跳传播到管家和盟友；只有共享证据和关系阈值都满足才形成联盟。” |
| 02:28–02:35 | 回到 README 的复现命令 | “代码、Windows 构建、公开原创世界包和全部报告都可复现。” |

必须在成片中保留一次被拒绝的输入。它比只展示成功分支更能说明系统边界。

### 成片验收

- 时长 2:00–3:00；
- 单镜到底，画面内字幕可读；
- 至少出现一次 Unity 真实交互、一次世界版本变化、一次规则拒绝；
- 不展示 API Key、`.env`、本地小说全文或个人账户；
- 文件建议命名 `NovelSim-core-demo-v1.mp4`；
- README 中存在可访问的视频链接和结构化运行报告。

## 3. 10–15 分钟面试演示

### 0:00–1:00：问题与结论

“LLM-only 游戏 Agent 的核心风险不是文案不好，而是它会把意图、幻觉和世界事实
混在一起。我把系统拆成 LLM 高层决策、确定性状态机、受控工具和权威事件存储。
模型可以建议做什么，但不能自己宣布已经发生。”

展示 README 首屏的架构句和关键数字。

### 1:00–3:30：Unity 真实运行时

1. 启动 Windows 包；
2. WASD 接近 NPC，按 E；
3. 指出 NPC 的 NavMesh 行为、对话/物品/HUD 变化；
4. 打开 F1 面板，说明 `session_id`、世界版本和事件游标；
5. 重启客户端，展示从同一权威快照恢复。

重点说明：客户端掉线不会丢掉事实，也不能把本地动画状态写回服务端。

### 3:30–5:30：不可能行动与三层防线

输入“夜轻歌开飞机飞走了”，依次说明：

1. 时代概念门禁拒绝未注册飞机；
2. 即使模型给出 Patch，ActionPolicy 与 Capability/Affordance 仍会拒绝越权状态变化；
3. Narrator 只能引用已提交 `event_id`，所以失败不能被叙述成成功。

随后展示 `evaluation/reports/deterministic-v1.md` 中 G0–G3 的 6/4/1/0。

### 5:30–8:00：原创密信多 Agent 场景

执行：

```powershell
.\.venv\Scripts\python.exe -m examples.secret_letter.demo --route none
.\.venv\Scripts\python.exe -m examples.secret_letter.demo --route expose_truth
.\.venv\Scripts\python.exe -m examples.secret_letter.demo --route destroy_letter
```

讲清三件事：

- 没有玩家命令时，NPC 仍按 `observe → share → share → alliance` 推进；
- 每个 belief 都有来源事件和父证据，不会因为同场自动全知；
- 玩家公开真相、销毁密信、携信离开会得到不同的可回放终态。

展示 [`作品集架构与因果图.md`](作品集架构与因果图.md) 的联盟图。

### 8:00–10:30：评测，而不是挑最好看的样本

展示两份报告：

- `evaluation/reports/real-llm-v1.md`：20/20 完整运行、18/20 目标成功、
  45 次调用、49,255 Token、P50/P95 10.554s/16.469s；
- `evaluation/reports/pairwise-strong-v1.md`：与同模型 direct-prompt 强基线
  最终 3–3。

主动说明两条 `INVALID_ACTION` 失败被保留；主观结果没有整体领先，结构化叙事的
优势目前只出现在三个多角色取衣冲突样本。这样比只报胜场更可信。

### 10:30–12:00：工程可复现

展示：

- `start.cmd` / `novelsim.ps1` 一键启停；
- `pytest`、`python -m evaluation`、Unity test/build/smoke；
- `portfolio/worlds/secret-letter-v1.json` 及 SHA-256；
- GitHub Actions 的无真实模型费用门禁。

说明真实 LLM 回归是显式付费任务，不放进默认 CI。

### 12:00–15:00：按面试方向展开

- Game AI：状态机、行为恢复、NavMesh、服务器权威；
- LLM Agent：结构化输出、工具调用、认知隔离、反思记忆；
- 系统工程：SQLite 乐观锁、事件溯源、断点续跑、Telemetry；
- 评测：确定性门禁与 BOOKWORLD 风格 Pairwise 分层，不混淆主客观指标。

## 4. 常见追问

**为什么不用纯 LLM？**
因为提示词不能提供事务、权限或因果保证。G0 仅提示词在 6 个违规探针上全部放过，
G3 确定性闭环为 0。

**为什么不用 Redis/Kubernetes？**
求职版是本机单实例竖切片，SQLite 足以提供事务、版本和恢复。只有多实例广播成为
真实需求时才引入基础设施。

**Pairwise 3–3 是否说明方案无效？**
不是。客观正确性门禁与主观文风是两层指标。3–3 说明简单移动文案没有优势，
冲突场景有优势。6 题真人盲标与 Judge 一致 5/6、Cohen's κ 0.667，但样本小且
偏好没有标准答案，所以不外推。

**还有什么未完成？**
求职版收口项已经完成。A/B/C/D 长程真实模型消融放到作品集后续，当前交付保留
G0–G3、记忆消融和同模型强基线；2–3 分钟 Unity 本地证据成片与三路线 Windows
实包恢复验收均已完成。

真人标签已保存；以下命令可重复离线校准已有 Judge 报告，不会产生模型调用：

```powershell
.\.venv\Scripts\python.exe -m evaluation.pairwise_calibration `
  --report evaluation\reports\pairwise-strong-v1.json `
  --labels evaluation\human_labels_strong_v1.jsonl `
  --json evaluation\reports\pairwise-strong-calibrated-v1.json `
  --markdown evaluation\reports\pairwise-strong-calibrated-v1.md
```
