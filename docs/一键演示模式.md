# NovelSim 一键演示模式

## 目的

招聘方不需要配置模型、数据库或 Unity，打开 Web 页面后点击顶栏“一键演示”，
即可在数秒内看到 NovelSim 的三个核心能力。所有案例均使用本地确定性链路，
`requires_api_key=false`，不会产生模型调用或费用。

## 三条案例

| case_id | 演示能力 | 关键证据 | 权威终态 |
|---|---|---|---|
| `invalid_airplane` | 世界规则门禁 | `WORLD_CONCEPT_UNAVAILABLE` | `v0`，没有事件提交 |
| `valid_intervention` | 合法玩家行动 | `pick_up → destroy_item` | `v2`，密信被销毁 |
| `multi_agent` | NPC 自主协作 | 5 个工具调用、2 条传播记录、1 个联盟 | `v5`，防卫联盟形成 |

“合法提交”和“场景目标达成”是两个独立指标。销毁密信案例中的两个工具调用都
成功提交，但它中断了原本的 NPC 防卫联盟目标，因此
`objective_satisfied=false`。这不是失败，而是玩家干预改变场景结局的证据。

## API

请求：

```http
POST /api/demo/runs
Content-Type: application/json

{"case_id":"multi_agent"}
```

响应沿用 `/api/session` 的标准会话结构，并增加：

```json
{
  "status": "ok",
  "session_id": "...",
  "state": {"version": 5},
  "turns": [],
  "demo": {
    "case_id": "multi_agent",
    "requires_api_key": false,
    "evidence": {
      "world_version": 5,
      "tool_calls": 5,
      "propagation_count": 2,
      "alliance_count": 1,
      "objective_satisfied": true
    }
  }
}
```

每次演示创建一条独立世界线。规则拒绝、底层 Agent 工具轨迹和聚合演示结果都会
写入剧情历史；刷新页面或重启后端后，可以通过同一 `session_id` 恢复相同状态和
展示证据。

## 代码链路

```text
DemoLauncher.vue
  → POST /api/demo/runs
    ├─ invalid_airplane
    │   → 华容巷 WorldState
    │   → ActionParser 世界概念预检
    │   → REJECTED，不调用 LLM、不提交事件
    ├─ valid_intervention
    │   → 密信疑云确定性玩家路线
    │   → ToolRegistry / PatchValidator / SQLite
    └─ multi_agent
        → SceneController / AgentExecutionStateMachine
        → 观察 → 信息传播 → 联盟门禁 → SQLite
```

前端把底层 `tool_call` 审计记录渲染成 Agent 工具轨迹卡，而不是伪装成自然语言
对白。右侧规则面板继续展示最新 ACCEPTED/REJECTED 判定，顶部证据条展示版本、
工具调用、传播记录和联盟数量。

## 推荐录屏顺序

1. 打开 `http://127.0.0.1:8000/`，点击“一键演示”。
2. 先运行“非法行动：开飞机”，强调 `v0` 未变化。
3. 再运行“合法行动：销毁密信”，展示 2 个已提交工具事件与 `v2`。
4. 最后运行“自主行为：传播与结盟”，展示 5 步工具轨迹、2 条传播和 1 个联盟。
5. 刷新浏览器，证明最后一条世界线及轨迹能够恢复。
